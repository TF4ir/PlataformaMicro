## 2. Decisiones Técnicas Tomadas

1. **Estrategia de Preservación de Trabajo**:
   - Todo el trabajo pendiente en `main` fue respaldado en `/tmp/backup_r1/changes.patch` y `/tmp/backup_r1/uncommitted_all.tar.gz`.
   - Se creó la rama `release/r1-2026-11` directamente desde HEAD (`299f6e1`) preservando los archivos sin ninguna operación destructiva (`git reset`, `clean` o `restore`).
2. **Endurecimiento de Despliegue OpenNext / Cloudflare**:
   - Para impedir la publicación accidental de compilaciones obsoletas, `scripts/release-cloudflare.mjs` purga explícitamente `apps/web/.open-next` y `apps/web/.next` antes de compilar.
   - Se valida la compatibilidad de opciones CLI con Wrangler 4.158.0: se utilizan `--message` (descripción del release), `--tag` (etiqueta con Build ID) y `--dry-run`.
   - Por defecto, el script de release opera en modo seguro `--dry-run` a menos que se invoque expresamente con `--publish`.
   - `scripts/verify-release-artifact.mjs` implementa un analizador sintáctico de JSONC caracter por caracter para evitar que cadenas con `https://` sean truncadas como comentarios de una línea.
3. **Escaneo de Sentinelas Inseguros (P0-1)**:
   - Se definieron 5 sentinelas prohibidos en bundles de cliente: `startAttemptFromSupabase`, `submitAnswerFromSupabase`, `submitAttemptFromSupabase`, `getAttemptResultsFromSupabase` y `getStudentActivityFromSupabase`.
   - `scripts/verify-release-artifact.mjs` escanea los 127 archivos JavaScript generados en `.open-next/` abortando con error fatal si detecta alguna de estas funciones.
4. **Sincronización Determinista de Contratos OpenAPI (C5)**:
   - Se desacopla la gobernanza (título, descripción, contacto, servidores productivos y locales, esquema `BearerAuth` de GoTrue) de la generación canónica de FastAPI (`app.openapi()`).
   - Se ordenan lexicográficamente todas las rutas y schemas para asegurar diffs limpios y reproducibilidad binaria en el tiempo.
   - El modo `--check` se ejecuta en CI y falla si existe discrepancia sin tocar el archivo en disco.
5. **Aislamiento de Fallback Docente (C8)**:
   - En `apps/web/src/lib/api/teacher.ts`, se restringió el fallback a Supabase estrictamente a fallas de transporte (código HTTP 0 o `TypeError: fetch failed`).
   - Errores de negocio y autenticación (401, 403, 429, 500, 503) se propagan directamente a la interfaz con su mensaje real, impidiendo que el cliente consulte tablas de Supabase cuando el servicio FastAPI rechaza la petición.
6. **Alineación de API de Microcontenidos (C9)**:
   - Se corrigió el método HTTP a `PATCH` según la definición del endpoint `/api/v1/microcontents/{id}` de FastAPI.
   - Se corrigió el parámetro de consulta a `kc_id` para coincidir con la firma canónica del backend.
   - Se removió el parámetro `status` del frontend ya que no está soportado por el router backend.

## 6. Verificación de Reproducibilidad

1. **Árbol Limpio Obligatorio**: `scripts/release-cloudflare.mjs` rechaza cualquier intento de publicación si existen archivos no rastreados o modificaciones locales sin commitear.
2. **Purga Pre-compilación**: Se eliminan `.open-next` y `.next` antes de iniciar la construcción, evitando publicar artefactos antiguos o fragmentos de builds abortados.
3. **Validación de Frescura**: El validador exige que el `mtime` del bundle `worker.js` sea posterior al timestamp de inicio del build actual.
4. **Manifiesto de Procedencia del Artefacto**: Cada artefacto verificado genera un archivo `apps/web/.open-next/release-manifest.json` que registra el hash de commit exacto, rama, Next.js Build ID, tamaño del paquete y fecha UTC.

## 8. Instrucciones de Revisión y Publicación

### Pasos para Revisión por Pares (Local)
1. Posicionarse en la rama de release:
   ```bash
   git checkout release/r1-2026-11
   ```
2. Verificar que el árbol de trabajo se encuentra limpio:
   ```bash
   git status
   ```
3. Ejecutar la suite de pruebas automatizadas:
   ```bash
   npm test
   npm run type-check
   npm run lint
   npm run openapi:check
   ```
4. Ejecutar el pipeline de validación en modo dry-run:
   ```bash
   node scripts/release-cloudflare.mjs --dry-run
   ```

### Pasos para Despliegue a Producción (Una vez aprobado)
*Nota: No ejecutar hasta contar con la autorización explícita del Tech Lead / release coordinator.*
1. Publicar a Cloudflare Workers:
   ```bash
   node scripts/release-cloudflare.mjs --publish
   ```
2. Verificar el despliegue con Wrangler y comprobar la disponibilidad del endpoint web.
